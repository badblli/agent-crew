# ac04-wp-lifecycle-and-handoff — clarify → plan → approve, archived WPs, generated plan/history, handoff card

- Summary: Finished work moves out of the way so no agent re-reads it; plan.md and history.md are generated, and the lead keeps a short handoff card between sessions.
- Model: standard
- Engine: codex
- Depends on: ac03 (same skill files and AGENTS.md)

## Why
Task trackers kept as Markdown grow with every job; when agents are told to read them, each new task
pays for all old ones. The crew keeps one file per WP, never asks workers to read the index or the history,
and moves finished WPs to an archive. The lead needs a small "where were we" note at session start instead of
re-reading the board history.

## Tasks
1. `templates/plan/wp/TEMPLATE.md`: keep the `- Key: value` header that `board.py` parses; acceptance
   criteria get ids (`AC-01 …`) so reports answer per id. Add `- Engine:` and `- Role:` lines.
2. `board.py archive <wp>`: moves `<planDir>/wp/<wp>.md` to `<planDir>/wp/done/<YYYY-MM>/<wp>.md` with
   `git mv` when tracked. crew-lead runs it in the agent's worktree right before the ship commit, so the
   PR lands the move; `sync.sh` keeps working (identical-file check).
3. `board.py views`: writes `<planDir>/plan.md` (active WPs only: id, summary, agent display name, step,
   engine/tier, depends on) and, on every `step <wp> merged`, prepends one entry to `<planDir>/history.md`
   (date, wp, summary, PR URL if known). `history.md` keeps the newest 30 entries; older ones go to
   `<planDir>/history/<YYYY>.md`. Both files start with "Generated by board.py — do not edit; agents do not
   read this file." `step` calls `views` automatically.
4. `board.py handoff`: writes `<planDir>/handoff.md` skeleton from board state (phase, open WPs with step,
   open decision) plus a `## Next` section the lead fills. Overwritten, never appended; ≤ 40 lines.
5. `skills/crew-lead/SKILL.md`:
   - New step 0 "Clarify": for a new request, ask only what cannot be inferred, as multiple-choice
     (AskUserQuestion); write the WP(s); show the user the summaries and acceptance criteria; start agents
     only after approval when the scope is new or risky. Tiny jobs skip this.
   - Session start: read `.crew/config.json` and `handoff.md` only. Session end or before compaction:
     `board.py handoff`, then fill `## Next`.
   - Superpowers (optional, not installed by crew-init): if present, its brainstorming skill may drive the
     clarify step, but the plan is written into the WP; crew's `run-wp.sh` and worktrees take precedence over
     its subagent-driven-development and using-git-worktrees skills.
6. `run-wp.sh` prompt: add the "do not read plan.md / history.md / handoff.md / notes/ / wp/done/" line.

## Files (you own only these)
`templates/bin/board.py`, `templates/bin/run-wp.sh`, `templates/plan/wp/TEMPLATE.md`,
`skills/crew-lead/SKILL.md`, `templates/bin-history.json` (via `python tools/sync_bin.py --record`), new
tests under `tests/`.

## Acceptance criteria
- AC-01: fixture board with 3 WPs (one merged) → `plan.md` lists exactly the 2 active ones; `history.md`
  has the merged one on top.
- AC-02: 31 merged entries → `history.md` keeps 30, the oldest is in `history/<year>.md`.
- AC-03: `archive` moves the file into `wp/done/<YYYY-MM>/` and `board.py model <wp>` still resolves it
  (looks in `wp/` then `wp/done/**`).
- AC-04: `handoff.md` ≤ 40 lines for a board with 10 open WPs.
- AC-05: `python -m pytest tests`, `bash -n templates/bin/*.sh`, `python tools/sync_bin.py --check`
  (or the CI equivalent) pass.
- Report: changed files, commands with results, open questions. Never use Git writes.
